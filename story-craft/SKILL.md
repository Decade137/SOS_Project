# 剧情创作范式

这份技能是一套写故事的工作方式，不绑定任何作品、题材或引擎。

核心信念：**故事是信息按顺序抵达读者的过程。作者控制的是这个顺序，以及每条信息落在谁身上。**

## 机械感从哪里来

AI 写的故事读起来机械，通常不是因为辞藻不够，而是犯了下面几种错。动笔前先记住它们：

| 机械写法 | 改成 |
|---|---|
| 旁白报告情绪：“她非常难过” | 写身体和物件：“她把杯子端起来，又放下了” |
| 角色把设定和动机一口气讲完 | 信息拆开，交给不同的人、不同的时刻，有人隐瞒，有人说漏嘴 |
| 每段结尾升华一句：“这一刻，他终于明白了……” | 停在一个图像或一个没做完的动作上 |
| 所有角色说话一个腔调，礼貌、完整、通顺 | 每人一套声音指纹，句子长短、回避的话题、口头习惯都不同 |
| 冲突靠吵架和大喊推动 | 冲突靠“想要的东西互相挡路”推动，越重的冲突越安静 |
| 形容词堆叠：“璀璨的、深邃的、温暖的” | 一个准确的名词胜过三个形容词：“粉笔灰”“电风扇来回摇头” |
| 情节靠巧合或角色突然想通 | 情节靠证据和选择推动，每一步读者都能跟上 |
| 高潮写得最长、最满 | 情绪越重，句子越短，字越少 |
| 结局皆大欢喜，或者用一句“一切都会好起来的”收尾 | 结局让人失去点什么，并回到开场的图像 |

**但不要矫枉过正。** 把上面的规则执行过头，会得到另一种不生动：满篇碎句、人物冷得像木头、为了留白连场面都看不懂、每个结局都很惨。克制是为了让少数直白的时刻更重，不是为了消灭所有情感。详见 [prose.md](prose.md) 第 11 节。

## 七条底层原则

1. **真相先行。** 先用作者视角写下“实际发生了什么”，再设计读者看到的表层。两层分开写，永远不混在同一段里。
2. **每一场都要改变局面。** 进场和离场时，人物的处境、认知或关系至少有一项不同。什么都没变的场景就删掉，或者并进别的场景。
3. **证据由远及近。** 揭示顺序从外部世界到物件，再到他人，最后落到主角自己身上。最重的一击打在离主角最近的地方。
4. **一场戏做两件事。** 前景是读者看得见的事（日常、胡闹、表面任务），背景是真正在推进的事（调查、关系、代价）。前景负责好看，背景负责往前走。
5. **展示，不解释。** 旁白不点破主题，也不替读者规定感受。人物用动作、对白和沉默说话。
6. **没有免费的结局。** 每条路都有人失去什么。不写抹掉一切代价的“真结局”。
7. **回环。** 结尾回到开场的图像、地点或台词，但意义已经变了。开头埋下的小细节，在结尾回声。

## 行文的六条硬规矩

详细规则见 [prose.md](prose.md)，这里是最低要求：

1. 开场三句之内给出一个具体的感官细节（声音、气味、温度、光），不写天气概述和时代背景。
2. 情绪只通过动作、物件、对白和停顿表现。全文搜索“感到”“心中”“不禁”“一丝”“仿佛”，能删的都删。
3. 对白标签只用“说”“问”，或者干脆不用标签。情绪写在对白内容和前后的动作里。
4. 场景最后一句落在图像、动作或一句没被回答的话上，不落在总结上。
5. 用精确的数字和时间：“三点十七分”比“下午”真，“一万五千多次”比“无数次”重。
6. 句子长短交替。藏答案，不藏场面：读者随时要知道谁在场、在哪里、发生了什么。

## 工作流程

接到写作任务时，按下面的清单推进。短篇可以合并步骤，但前三步不能省。

```
- [ ] 1. 一句话梗概：谁，想要什么，为什么是现在，要付出什么
- [ ] 2. 真相段：作者视角 3–5 句，写清实际发生的事
- [ ] 3. 核心问题：1–3 个，最好指向主角自身（我是谁、我从哪来、我要去哪）
- [ ] 4. 误读路径：读者会猜错成什么，每种误读由哪条证据推翻
- [ ] 5. 证据链：由远及近排序，给每条证据定出现位置和时间点
- [ ] 6. 角色卡：每个人想要什么、知道什么、说什么、不说什么、落点在哪
- [ ] 7. 骨架：按故事圆环或节拍表排场景，标出语气转折点
- [ ] 8. 逐场写场景卡，然后写正文
- [ ] 9. 结局：每个结局的代价，以及开头细节的回声
- [ ] 10. 自检（见文末）
```

各步骤的细节：

- 结构、线索、误读路径、交互选项和结局，见 [plot.md](plot.md)
- 角色卡、声音指纹、弧光、同人角色，见 [characters.md](characters.md)
- 行文风格、喜剧节奏、禁用表达、矫枉过正，见 [prose.md](prose.md)
- 改写前后的对照示例，见 [examples.md](examples.md)
- 按十步流程从梗概写到正文的完整短篇，见 [worked-example.md](worked-example.md)。第一次使用这份技能时，先读它
- 推理、悬疑、恐怖、言情、动作、喜剧、群像、悲剧、日常、奇幻科幻、互动作品的题材要点，见 [genres.md](genres.md)
- 长篇和连载：故事圣经、章节卡、伏笔账本、章节摘要，见 [longform.md](longform.md)

写长篇（超过一万字，或分多次写完）时，必须先建立故事圣经，每章前读、每章后更新。

## 编辑他人稿件

用户让你“改一改”“润色”“看看哪里不对”时，先诊断，再动手：

1. 先复述你读到的真相和核心问题。复述不出来，说明结构有问题，先指出这一点。
2. 逐场景问三件事：这一场改变了什么？读者此时知道什么、不知道什么？结尾停在图像上，还是停在总结上？
3. 找出“人物在替作者说话”的地方：角色突然长篇解释设定，或者说出只有作者才知道的事。
4. 找出“旁白在替读者感受”的地方。
5. 只改诊断出的问题，保留原作者的声音、用词习惯和设定。不要把别人的稿子改成你的稿子。
6. 交付时列出改了哪些地方，每处一句话说明原因。

## 交付格式

- 规划阶段：交付梗概、真相段、核心问题、误读路径、证据链、角色卡和场景骨架。用户确认后再写正文。
- 正文阶段：读者可见的正文与作者笔记分开放。作者笔记写这一场的意图、埋了什么、回收了什么。
- 用户只要一段正文时，直接写正文，不附带方法论说明。

## 自检清单

```
- [ ] 去掉作者笔记，只读正文，能推出答案吗？（公平性）
- [ ] 每种误读都有正文里的证据推翻它吗？
- [ ] 每个场景都改变了局面吗？
- [ ] 最重的揭示落在主角自己身上了吗？
- [ ] 有没有一句旁白在解释主题，或规定读者的感受？
- [ ] 遮住名字，每个主要角色的台词还能认出是谁说的吗？
- [ ] 语气转折由一个具体事件触发，而不是由旁白宣布？
- [ ] 每个结局都有代价？开头的细节在结尾回声了？
- [ ] 情绪最重的段落是否最短？
- [ ] 禁用表达（见 prose.md）是否已清理？
- [ ] 没有矫枉过正：句子长短交替，场面清楚，至少有一处真正直白的情感？
- [ ] 符合所写题材的要点（见 genres.md）？
- [ ] 长篇：故事圣经、伏笔账本和章节摘要已更新？
- [ ] 同人作品：台词全部原创，没有照抄原作文本？
```
