# 记忆

英文 `Docs/MEMORY.md` 为准。本文件只复述同一批事实。

## 技术栈

- 仓库：git，分支 `main`，远程 `https://github.com/Decade137/SOS_Project.git`。
- 选定的运行时：.NET 10（`net10.0`）上的 C# 控制台程序。发布目标是 Windows x64 自包含单文件 exe。源代码工程是 `Game/SOS_Project.csproj`；本地发布文件位于 `Game/bin/Release/net10.0/win-x64/publish/SOS_Project.exe`。
- 当前工作区是 `D:\MyProject\SOS_Project`。它不是 Unity 工程。

## 产品

- 目标：单人 C# 控制台游戏，在 Windows 上玩，发布成一个 exe。以正文为主，偶尔用控制台颜色画 `■` 图。玩家用 W/S 在编号选项间移动、按 Enter 确认，并扮演自己。玩法是推理解谜。剧本模块用类似《克苏鲁的呼唤》（COC）跑团的结构。故事世界是《凉宫春日的忧郁》。约定见 `Docs/GAME_DESIGN.md`。
- 当前实现：已有第 0 号完整 Markdown 剧本，以及涵盖开场、S00—S16、K01—K10、H01—H04、E01/E02 的 C# 控制台程序，含唯一存档位、送返结局的限定范围清理、逐字显示与 W/S 选项菜单。当前演出已通过 .NET 10 Release 构建及 Windows x64 单文件发布。双结局与临时发布副本自删在旧版上验证过；当前演出尚未试玩。
- 2026-09-24 的呈现参照：Windows `cmd` 窗口（深色背景、版本横幅、路径提示符）。

## 用户偏好

- 用户 le 用中文沟通，习惯直接在代码里工作。
- 会话记录保持简短，除非明确要求展开。
- 没有明确要求时，不提交、不编译、不启动引擎。
- 中文镜像与英文文档事实一致。英文为准。
- 用户已要求直接写完整剧本；正文须有趣，正史角色的原创对白和行为须符合原有设定，玩家可见叙述以第一人称为主。

## 决定

- 2026-09-24：「类似 COC」指 `Docs/GAME_DESIGN.md` 里的模块结构（主持人简报、时间线、人物、地点、线索、场景、选项、检定、结局、手稿）。不采用 Chaosium 规则原文、理智值或神话生物数值。
- 2026-09-24：程序担任主持人（KP）。一名人类玩家。玩家扮演自己，不另起名字，也不担任正史角色。先前的第二人称方向对第一份模块已被取代：这份模块的叙述和选项使用中文第一人称。其他模块的视角仍未定。
- 2026-09-24：玩家选择编号选项。谜题结论只在所需线索找到之后出现。同日已取代：「不做检定、不用骰子、没有技能表。」技能表仍然不用。检定已恢复，见下一条。
- 2026-09-24：有些剧情直接显示选项。有些剧情由属性检定决定当前显示哪些剧情选项。玩家选择检定的属性。成功和失败各自点名看得见的那一部分。属性名称、玩家数值，以及掷骰或目标值的做法仍未定。同日已取代：检定那一拍不写选项列表。
- 2026-09-24：通常输出正文。可选画面是 `■` 加控制台颜色，用 `Console.Write` 打印。
- 2026-09-24：主要玩法是推理解谜。
- 2026-09-24：剧本是符合该标题约定的 Markdown。引擎用的数据格式等到开始实现再定。
- 2026-09-24：这是非官方同人项目。已出版正文、剧本、歌词和官方素材不复制进仓库。
- 2026-09-24：运行时是 C# 控制台程序。用户要求之前不搭建工程。不添加 Unity。
- 2026-09-24：发布物是 .NET 10 上的 Windows x64 自包含单文件控制台 exe。玩家不必安装运行时。.NET 8 和 .NET 9 都在 2026-11-10 结束支持。本机预编译（Native AOT）先不用；它需要 Visual Studio 的 C++ 生成工具，留到以后再决定要不要换这种发布方式。
- 2026-09-24：第一份模块的核心设定：从《漫无止境的八月》分出异常世界线，SOS 团来到以重庆地貌为灵感的 2026 年中国城市，遇见玩家。反复穿越 2009—2026 年、异空间，以及与外星科技／资讯统合思念体有关的人工智能，共同呈现城市、社会和人心的变化。故事围绕「我是谁、我从哪来、我到哪去」；最终揭示玩家是春日创造的异常世界线居民。双结局是送团员返回正常世界线并删除本游戏本地 exe 和存档，或留在看似真实的创造世界中。整体语气以活泼喜剧为主，接近真相时转严肃。正史角色的对白须原创且符合人物。
- 2026-09-24：第一份模块以公平的推理解谜为主：线索的暗示自然藏在叙述和对白里，跨年代证据让玩家自行推出答案，真相要令人豁然开朗，不能只靠角色集中解释。主持人侧仍记录线索 id 和揭示条件。
- 2026-09-24：玩家看过《凉宫春日》的动画，一开始就知道春日近乎神明的改写世界能力。哲学三问必须问向玩家自己的身份、来处与去向。已有知识既是调查优势，也可能造成误判；谜题重点是玩家为何拥有这份知识、为何存在于支线，而不是春日有没有能力。不要替现实玩家编造个人履历。
- 2026-09-24：第一份完整模块是 `Scenarios/00-zero-floor.md`，使用中文第一人称、无名的虚构山城、空间路线谜、跨年代母女支线和外星 AI 观测谜。以玩家为中心按八阶段故事圆环推进，在开场外廊回环并作最终选择；成文不出现真实城市或地标名称。属性系统未定，这份模块只用直接选项。
- 2026-09-24：用户要求根据已写剧本开始编程。`Game/SOS_Project.csproj` 面向 `net10.0`；`Game/Program.cs`、`Game/Story.cs` 和 `Game/StoryRunner.cs` 分别实现控制台入口、场景与选项模型，以及运行循环。`Scenarios/ZeroFloor.Play.cs` 是根据 `Scenarios/00-zero-floor.md` 编写、编译进程序的剧情数据，目前只接入开场、S00—S05、K01—K03 和 H01 初版。运行循环处理编号选项、线索和旗标条件及效果、已发现线索与手稿的重读，以及可选的彩色 `■` 画面。在 S05，按 `0` 可重读手稿，两个编号选项都可结束预览。玩家输出不含主持人笔记。源码尚未构建或测试。
- 2026-09-27：第一版完整可玩内容限于第 0 号剧本，采用直接选项；属性检定与可追踪资源仍是后续问题。唯一的带版本号存档位于 `%LOCALAPPDATA%/SOS_Project/save.bin`，每次剧情选择后写入，但送返结局最后确认除外；若结局中断，可以回到确认页重试。启动时可继续或替换。送返结局在剧情内两次确认并显示结局文字后删除本作存档，并在已发布的 Windows 单文件版本中尝试于退出后删除自己的 `SOS_Project.exe`；源码运行或非 Windows 平台只删除存档。留下结局保留两者。
- 2026-09-27：经用户明确允许，已成功构建 .NET 10 控制台程序，试玩第 0 号剧本的双结局，发布 Windows x64 自包含单文件 exe，并观察到临时副本在 E01 后自删。发布产物保留在本地，由 Git 忽略。
- 2026-09-27：玩家可见的剧情文字逐字显示，显示完毕后才出现选项。W/S 在编号选项间移动，Enter 确认，取代交互游玩时输入编号；重读已发现材料时立即显示全文。按键可立即补完当前文字。
