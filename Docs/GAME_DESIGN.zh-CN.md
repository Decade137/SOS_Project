# 游戏设计约定

状态：第 0 号剧本在 Ren'Py 8.5.3 窗口中运行。当前模块是 2026-09-30 的剧情。`pack.bat` 会生成 `Build/SOS_Project/SOS_Project.exe`。英文 `Docs/GAME_DESIGN.md` 为准。

## 产品

SOS_Project 是窗口里的单人文字游戏。玩家阅读叙述，用 W/S 或方向键在圆点选项间移动，并按 Enter 或点击确认。每段故事是一份剧本模块，结构类似《克苏鲁的呼唤》跑团模组。故事世界是《凉宫春日的忧郁》。玩法是推理解谜。

这是非官方同人项目。不复制小说正文、动画脚本、歌词或官方素材。

## 决定

- 运行时是 Ren'Py 8.5.3。工程在 `Play/`。文字画在深色窗口里。`pack.bat` 在缺少 SDK 时下载 Ren'Py，并打出 Windows x64 游戏目录；玩家运行 `Build/SOS_Project/SOS_Project.exe`，不必安装 Ren'Py。本仓库不是 Unity 工程。不添加 Unity 文件，也不要把可玩版本改回 C# 控制台。
- 通常的画面是正文。一个场景可以另附一幅由彩色方块按 `■` 图案排成的图。这种图只是偶尔出现，不代替朗读文本。
- 程序担任主持人。一名玩家。玩家扮演自己，不是正史角色，也不另起名字。第一份模块的叙述和选项使用中文第一人称；先前的第二人称方向对该模块已被取代。
- 玩家可见的剧情文字逐字显示，显示完毕后才出现选项。任意键或点击可立即补完当前文字块；重读已发现材料时立即显示全文。独立首页提供新游戏、读存档和退出；无有效存档时读存档不可选。场景、行动反馈、档案和结局各自换页。文字排在蓝黑底色页面中央的一栏里，剧情正文用衬线字体。对白为青色，叙述为偏暖的米白色。每个结局页有各自的底色。页面可用鼠标滚轮滚动。继续提示紧跟正文，多出来的空白留在提示下方。所有可见菜单项以 `·` 开头；W/S 或方向键使选中项全文变为青色，Enter 确认。点击选项也可以确认。
- 用来解开或下结论的选项要写明它需要的线索 id，并且只在这些线索已经找到之后才出现。其他选项可以不依赖线索。玩家选中的每一项都要改变局面。
- 有些剧情直接显示全部剧情选项。有些剧情由属性检定决定当前显示哪些剧情选项。选项仍属于这一拍。检定只决定其中哪些看得见。
- 在检定那一拍，玩家选择检定哪项属性。成功和失败各自点名这一拍选项里的一部分。玩家再从显示出来的选项里选一项。没有技能表。属性名称、玩家的数值，以及掷骰或目标值的做法仍未定。同日已取代：检定那一拍不写选项列表，以及检定直接跳进分支。
- 「类似 COC」指本文件里的模块结构。不是采用 Chaosium 规则书、理智值或神话生物数值。
- 剧本的事实来源是符合下列标题的 Markdown。程序使用 `Play/game/story_data.py` 作为从 Markdown 整理出来的明确玩家剧情数据；运行时不解析主持人笔记。
- 第一版完整可玩内容是使用直接选项的第 0 号剧本。该模块不用属性检定或可追踪资源，因此这两套规则仍留给后续系统设计。
- 唯一存档位于 `%LOCALAPPDATA%/SOS_Project/save.json`，格式版本 4。每次剧情选择后自动保存，但送返结局的最后确认除外：清理前保留确认页存档，若结局中断，可再次确认。独立首页提供新游戏、读存档和退出；新游戏替换该存档，无可用存档时读存档不可选。带版本号的存档保存当前场景、已发现材料、旗标、文本选择和已完成的留下结局。旧的 `save.bin` 不会被读取。
- 送返结局必须经过剧本中两次明确确认。这两次确认都在剧情里：玩家送五人回去，并知道这个八月合上时自己也在里面。玩家可见的叙述、选项、手稿和结局页不提存档、Windows 或可执行文件。结局文字显示完毕后，程序删除本作存档，不再另开一页报告。在打好包的 Windows 版里，限定范围的辅助进程再尝试于退出后只删除该目录中的 `SOS_Project.exe`，删除前核对 SHA-256。绝不删除其他文件。若无法安排，游戏照样结束，不要求玩家去删文件。用 SDK 运行或在非 Windows 平台运行时，只删存档。留下结局和重来结局保留两者。

## 模块结构

每份剧本按这个顺序使用这些章节。用不到的章节保留，下面写 `None.`。

1. **标题信息** — 标题、一句话简介、预计游玩时间、玩家角色假设（玩家自己）、语气说明。
2. **主持人简报** — 实际上发生了什么。玩家文本不得包含这部分。
3. **时间线** — 开场时已经成立的事实，按顺序写。
4. **开场** — 玩家看到的、事情为什么开始。
5. **人物** — 每个角色一小节。
6. **地点** — 每个地点一小节。
7. **线索** — 每条线索一小节。
8. **场景** — 可游玩的节拍。进入条件可以是地点、线索或时钟。
9. **选项** — 属于这一拍的剧情选项。
10. **检定** — 可选。玩家选择检定哪项属性。检定结果决定当前显示哪些选项。
11. **结局** — 结局或重大转折。每个都写明被选中的条件。
12. **手稿** — 玩家可以再次阅读的文本，例如传单、便条、文章。

### 人物

- 名字，以及和这件事的关系
- 想要什么
- 知道什么（线索或时间线条目的 id）
- 当众会说什么
- 不会主动说什么（仅主持人）

### 地点

- 第一印象（玩家）
- 主持人笔记
- 谁在这里
- 这里能找到哪些线索
- 玩家接下来能去哪里

### 线索

- 玩家可见的摘要，按「找到时看到的样子」来写
- 在哪里找到
- 若由某个选项揭示，是哪一个选项
- 它指向什么
- 主持人知道的含义
- 若这里由玩家选择检定属性：对应的检定 id

一条线索必须有 id 和揭示条件才算数。埋在散文里的暗示不是线索。直接选项可以揭示它。用检定揭示它的那一拍还要指定一次检定。

### 场景

- 进入条件
- 朗读文本
- 可选画面说明（这幅 `■` 图表现什么，或 `None.`）
- 主持人笔记
- 这一拍的剧情选项，以及每个选项通向哪里
- 显示方式：`直接选项` 或 `属性检定`
- 若是直接选项：显示这份列表。这一拍没有检定。
- 若是属性检定：写下检定 id。检定决定这些选项里当前显示哪些。

### 选项

- 玩家看到的文字
- 出现前需要的线索 id，或没有
- 通向哪里
- 改变了什么

已经出现的选项一旦被选中，就要改变局面。结论类选项在所需线索找到之前不进入列表。

### 检定

- 哪一拍提供这次选择
- 玩家可以选择的属性
- 对其中每一项属性：成功时显示这一拍的哪些选项，失败时显示哪些

掷骰、目标值和完整属性列表还没定。每个结果点名的都是这一拍里已经有的选项。没被点名的选项保持隐藏。

### 结局

- 条件
- 朗读文本
- 之后仍然成立的事实

## 游玩循环

1. 逐字显示开场或当前场景的朗读文本；按键或点击可补完当前文字块。
2. 如果这一拍有图，用彩色方块显示它。没有图就跳过。
3. 文字显示完毕后，如果这一拍标明 `直接选项`，就显示它的圆点剧情选项。
4. 如果这一拍标明 `属性检定`，就显示属性选项。玩家选择一项属性。结算检定，然后只显示该结果点名的当前剧情选项。
5. 玩家用 W/S 或方向键在显示的选项间移动，按 Enter 或点击确认一项剧情选项。
6. 把它结算成叙述，外加一次状态变化：一条线索、一个新场景、一段关系变化，或一个结局。
7. 允许玩家重读手稿和已经找到的线索。
8. 到达结局后停止。

### 第 0 号剧本程序范围

`Play/game/script.rpy` 启动游戏。`Play/game/story_data.py` 存放开场、场景链、K01—K13、H01—H06（另含 H01_REVISED）和 E01—E03。较长的玩家正文从 `story_prose.py`、`story_long.py`、`story_more2.py`、`story_more3.py` 导入。`Play/game/engine.rpy` 逐字显示剧情，推进选项，处理线索与旗标的条件和效果，写入一份 JSON 存档，允许重读已发现材料，并在 E01 后删除存档、请求 Windows 只删除打好包的 `SOS_Project.exe`，且不把这一步显示出来。`Play/game/screens.rpy` 绘制页面。玩家输出不含主持人笔记。只有 E01 可以请求清理文件；E02 与 E03 保留存档和 exe。

首个模块只用直接选项。不运行自动测试套件。在仓库根目录用 `pack.bat` 打包。

## 故事边界

下面这些可以作为舞台。以后的剧本不是正式正史。

- 北高、SOS 团活动室，以及学校周围的城镇
- 凉宫春日、阿虚、长门有希、朝比奈实玖瑠、古泉一树
- 这个世界里本来就有的现象，包括封闭空间，以及团里非普通成员已经理解的事实

玩家扮演自己。第一份模块使用第一人称叙述。不把玩家写成正史角色，也不编造姓名或个人经历。

SOS 团成员向玩家自我介绍前，玩家可见的场景正文与选项反馈用眼前可见的外貌和动作指代，不直接显示姓名；介绍后可以使用姓名。

长门、朝比奈、古泉从不在春日面前暴露身份或谈论异常；阿虚同样保持沉默。按每个角色自己知道的事来写：团员不知道玩家早已认得他们。在玩家挑明之前，团员暗中调查玩家，并趁春日听不见时互相通报（第 0 号剧本里是告诉阿虚）。他们不向玩家解释自己的能力；玩家是靠偷听得知结果，而不是团员主动说出。玩家选项不得在春日面前提起内情。

每份剧本都是推理解谜：玩家收集线索，再选择由这些线索解锁的结论。标题信息里的语气说明要写明喜剧与调查压力如何分配。第一份模块以活泼喜剧开场，接近真相时转严肃。

正史角色若出场，说的是为本模块新写的台词。

第一份模块是 `Scenarios/00-zero-floor.md`，标题《凉宫春日的心愿》；剧情里的考试仍叫“异世界人入团考试”，文件名沿用旧名。故事发生在 2009-08-31 15:17 到零点，是《漫无止境的八月》某一次循环分出的支线，舞台是 SOS 团所在的无名小城。玩家从活动室的铁皮柜里走出，春日宣布这正是团里缺的“异世界人”，并主持一场搞笑的三关入团考试。每一关背后，长门、朝比奈、古泉分别暗中排除外星人、未来人、超能力者，并把结果告诉阿虚；玩家每次都偷听到了。S08 春日离开后，阿虚刚要向玩家说明，玩家先说出自己早就知道他们是谁。之后的线索显示支线正在把玩家写进来：春日八月二十日笔记本上的清单与玩家随身物品吻合，这本笔记本又多出一行字，阿虚对玩家刚选的句子产生既视感，玩家自己也记得一条春日当晚才做好的臂章。长门不会被改写的记录是独立对照。玩家由此推出：春日的愿望造出了自己，连同“我从另一个世界来”的记忆。春日始终不知道真相。笔记本出现变化之前以喜剧为主。故事按八阶段故事圆环推进，最终回到铁皮柜前选择。共有三个结局。选项会改变团员怎么对待玩家：进门的回答、日历上沉不沉默、跟谁去查、当场的那一叉、20:10 的那句话、捞不捞金鱼，以及要不要把少掉的勾指给春日。送回时朝比奈、阿虚、古泉的告别各写各的。玩家只亲自走一关，另外两关在春日出去买果汁时听完。K01–K09 仍在 S12C 的推论之前到齐。K11 是第六只杯子，K12 是空抽屉，K13 是 15:16 从柜子里向外拍的照片。错误推论可以各试一次，用这些线索当场驳回，不锁路线。不同选项收回不同的埋伏：谁倒的茶、站名是否对上车票、空椅子、抽屉里的红线，以及臂章出现之前阿虚是否先说出“不许弄丢”。最短一条大约 39,000 字、34 处选择，按仔细阅读大约两小时。这个数字没有在窗口里计时。没亲眼听到的检查在买果汁时补上，不再拖到 S08 才第一次整段说出。E01 送五人回去、关闭支线。玩家可见文字不说文件会被清掉；限定范围的清理仍在结局文字之后进行，没有报告页。E02 留下进入真正的九月，五人则从原世界线消失。E03 不作选择，暑假连同玩家一起回到 8 月 17 日。

玩家默认熟悉《凉宫春日》及 SOS 团的相关故事，知道春日可能改写世界；玩家可见的朗读与选项不直接解释这份熟悉的来源，而用角色反应、生活细节、时间轨迹和档案缺口体现它。哲学三问须围绕玩家自己的身份、来处，以及自己选择的去向。这份既有知识要成为需要验证的证据，也可能使玩家误判；不能把「春日有能力」留到最后当反转。不要给玩家安上编造的个人经历。

## 写作规则

- 玩家可见的句子和仅主持人可见的句子不放在同一段。
- 写原创句子。不誊抄已出版的小说、脚本或对白。
- 真正开始写模块之前，不创建 `Scenarios/`。
- 谜题的结论选项，在它需要的线索 id 找到之前，不放进列表。
- 暗示自然埋进场景叙述与对白。可发现的线索仍在主持人侧写明 id 和揭示条件；应让玩家先凭跨年代证据自己推出最终答案，再由角色说明。
- 每一拍都列出自己的剧情选项，并标明显示方式是 `直接选项` 或 `属性检定`。直接选项显示整份列表，不写检定。属性检定列出玩家可以选择的属性。每一项属性的成功和失败，都要点名当前这些选项里显示哪些。

## 范围之外

- 技能表、理智值，或 Chaosium 的角色卡
- 多人或人类主持人界面

## 未决问题

未来的系统设计仍有下列未决事项。第一份已写模块只使用直接选项，所以属性规则不挡住它的正文。

- 有哪些属性，玩家如何得到这些数值，以及检定如何结算（骰子和目标值，或其他比较方式）。
- 是否存在可追踪资源（压力、怪异度、声望）。不采用理智值。
