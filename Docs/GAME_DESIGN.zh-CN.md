# 游戏设计约定

状态：目标。还没有剧本正文，也还没有 C# 工程。英文 `Docs/GAME_DESIGN.md` 为准。

## 产品

SOS_Project 是单人文字游戏，呈现为一场控制台会话。玩家阅读叙述，并选择一个编号选项。每段故事是一份剧本模块，结构类似《克苏鲁的呼唤》跑团模组。故事世界是《凉宫春日的忧郁》。玩法是推理解谜。

这是非官方同人项目。不复制小说正文、动画脚本、歌词或官方素材。

## 决定

- 运行时是 C# 控制台程序。文字和画面都用 `Console.Write` / `Console.WriteLine` 输出。本仓库不是 Unity 工程。不添加 Unity 文件。用户要求实现之前，不创建这个 C# 工程。
- 通常的画面是正文。一个场景可以另附一幅由 `■` 和控制台颜色组成的图。这种图只是偶尔出现，不代替朗读文本。
- 程序担任主持人。一名玩家。玩家扮演自己，用第二人称称呼。玩家不是正史角色，也不另起名字。
- 场景给出编号列表。玩家选择一项。没有骰子，没有技能表。
- 用来解开或下结论的选项要写明它需要的线索 id，并且只在这些线索已经找到之后才出现。其他选项可以不依赖线索。玩家选中的每一项都要改变局面。
- 「类似 COC」指本文件里的模块结构。不是采用 Chaosium 规则书、理智值或神话生物数值。
- 剧本的事实来源是符合下列标题的 Markdown。引擎数据格式等到开始实现再定。

## 模块结构

每份剧本按这个顺序使用这些章节。用不到的章节保留，下面写 `None.`。

1. **标题信息** — 标题、一句话简介、预计游玩时间、玩家角色假设（玩家自己）、语气说明。
2. **主持人简报** — 实际上发生了什么。玩家文本不得包含这部分。
3. **时间线** — 开场时已经成立的事实，按顺序写。
4. **开场** — 玩家看到的、事情为什么开始。
5. **人物** — 每个角色一小节。
6. **地点** — 每个地点一小节。
7. **线索** — 每条线索一小节。
8. **场景** — 可游玩的节拍。进入条件可以是地点、线索或时钟。
9. **选项** — 场景里展示的编号选项。不掷骰。
10. **结局** — 结局或重大转折。每个都写明被选中的条件。
11. **手稿** — 玩家可以再次阅读的文本，例如传单、便条、文章。

### 人物

- 名字，以及和这件事的关系
- 想要什么
- 知道什么（线索或时间线条目的 id）
- 当众会说什么
- 不会主动说什么（仅主持人）

### 地点

- 第一印象（玩家）
- 主持人笔记
- 谁在这里
- 这里能找到哪些线索
- 玩家接下来能去哪里

### 线索

- 玩家可见的摘要，按「找到时看到的样子」来写
- 在哪里找到
- 若由某个选项揭示，是哪一个选项
- 它指向什么
- 主持人知道的含义

一条线索必须有 id 和揭示条件才算数。埋在散文里的暗示不是线索。

### 场景

- 进入条件
- 朗读文本
- 可选画面说明（这幅 `■` 图表现什么，或 `None.`）
- 主持人笔记
- 提供的选项
- 每个选项通向哪里

### 选项

- 玩家看到的文字
- 出现前需要的线索 id，或没有
- 通向哪里
- 改变了什么

已经出现的选项一旦被选中，就要改变局面。结论类选项在所需线索找到之前不进入列表。

### 结局

- 条件
- 朗读文本
- 之后仍然成立的事实

## 控制台循环（目标）

1. 显示开场，或当前场景的朗读文本。
2. 如果这一拍有图，用 `■` 和控制台颜色打印它。没有图就跳过。
3. 显示编号选项。
4. 玩家选择一项。
5. 把它结算成叙述，外加一次状态变化：一条线索、一个新场景、一段关系变化，或一个结局。
6. 允许玩家重读手稿和已经找到的线索。
7. 到达结局后停止。

## 故事边界

下面这些可以作为舞台。以后的剧本不是正式正史。

- 北高、SOS 团活动室，以及学校周围的城镇
- 凉宫春日、阿虚、长门有希、朝比奈实玖瑠、古泉一树
- 这个世界里本来就有的现象，包括封闭空间，以及团里非普通成员已经理解的事实

玩家扮演自己。用第二人称称呼。不把玩家写成正史角色，也不另起名字。

每份剧本都是推理解谜：玩家收集线索，再选择由这些线索解锁的结论。标题信息里的语气说明仍要写明正文偏向这部作品的喜剧，还是偏向调查的压力。这条说明和情节一起定。

正史角色若出场，说的是为本模块新写的台词。

## 写作规则

- 玩家可见的句子和仅主持人可见的句子不放在同一段。
- 写原创句子。不誊抄已出版的小说、脚本或对白。
- 真正开始写模块之前，不创建 `Scenarios/`。
- 谜题的结论选项，在它需要的线索 id 找到之前，不放进列表。

## 范围之外

- 存档格式
- 角色卡数值和骰子
- 多人或人类主持人界面
- 第一份剧本的情节

## 未决问题

这些项挡住第一份剧本大纲（`Docs/TODO.md` 的 DES-003）。运行时的选择不在此列。

- 第一件事件：用户还在决定第一份模块调查什么。
- 该模块的语气说明（喜剧或调查压力），和情节一起定。
- 玩家看到的语言。设计讨论用中文。
- 是否存在可追踪资源（压力、怪异度、声望）。不采用理智值。不使用骰子。
